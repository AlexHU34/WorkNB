# AERIS — как устроен проект

Каталог из ста игр и редактора. Каждая часть лежит в своей папке,
и понятно, зачем она нужна.

## Что где

| Папка | Что внутри | Нужна ли тебе |
|---|---|---|
| `index.html` | страница с каталогом 3D-игр | это готовая игра |
| `lang.html` | редактор кода BloomScript | да |
| `studio.html` | студия сцен | да |
| `src/app/` | логика каталога и сто игр | нет, это внутреннее |
| `src/engine/` | 3D-движок на WebGL2 | нет |
| `src/lang/` | язык BloomScript | нет |
| `src/studio/` | внутренности студии | нет |
| `src/data/` | диагностика ошибок, доступность | нет |
| `src/types/` | подсказки для редактора кода | нет |
| `tools/` | проверки качества и сборка | только если что-то чинишь |
| `docs/` | планы и заметки | по желанию |
| `dist/` | результат сборки, готовые сжатые файлы | нет, пересоздаётся |

## Три важных правила

**1. Готовые игры — это три файла, а не папка.**
`dist/min/` содержит `Aeris.html`, `BloomScript.html`,
`AerisStudio.html`. Именно они копируются в папку с играми. Их
можно отправить кому угодно: открыл файл — игра работает, без
интернета и без установки.

**2. Проверки запускаются все сразу.**
```
python tools/all-gates.py            # всё
python tools/all-gates.py --light    # быстрая часть, ~3 минуты
```
Это 39 быстрых проверок: синтаксис, движок, сто игр, 3D-движок,
редактор, студия, сейвы, облачная очередь, пускашка «игра в файл»,
снимки вида, панель родителей, безопасность вывода, доступность,
офлайн, вес, описания типов и другие. Если проверка падает — она сама
говорит, что именно сломалось.

Гейты идут **по одному**, а не одновременно. Это не медлительность:
по одному все проверки занимают около трёх минут, а одновременно
они растягивались до девяти и начинали зависать. Подробности в
`tools/all-gates.py`.

**3. Перед тем как отдать файлы, проверь.**
```
python build.py
```
Соберёт всё, сожмёт и прогоняет проверки по собранному файлу.

**4. Отправка не увезёт старую сборку.**
Перед каждой отправкой на GitHub срабатывает штамп из
`.githooks/pre-push`: он сверяет свежесть `site/` с исходниками и
смотрит, что в воркере проставлена метка кэша. Один раз на новой
машине включи его:
```
git config core.hooksPath .githooks
```
Обойти нарочно: `SKIP_STAMP=1 git push`.

**5. Чужие строки — только текстом.**
Всё, что пришло из базы или из чужого файла (имена в рейтинге, тексты
работ), попадает в страницу через `textContent`, а не `innerHTML`.
Однажды имя из рейтинга вставили как разметку — и любой мог выполнить
свой скрипт у всех игроков. Следит за этим `tools/security-gate.py`:
он не только читает код, но и подсовывает странице злую строку.
Подробности и что осталось сделать на сервере — в `docs/SECURITY-FIX.md`.

## Как добавить игру

Игры лежат в `src/app/games.js`, каждая — функция вида
`MODES.имя = function(){...}`. Имя становится адресом игры.
Список игр для меню — в `src/app/data.js`.

После правки:
```
python tools/run-tests.py        # сто игр должны пройти
python build.py
```

## Что ещё умеет проект

- **Игра одним файлом.** В студии есть кнопка «💾 Игра в файл»: она
  собирает страницу-пускалку, в которую вшиты движок, среда и сама
  игра. Такую страницу можно отправить другу — он откроет её двойным
  щелчком, и всё заработает даже без интернета. Проверяет это гейт
  `tools/runner-gate.py`.
- **Панель для взрослых.** `parents.html` объясняет, что за сайт, и
  даёт настройки на этом устройстве: предел времени в день, выключение
  облака и звука, сброс прогресса. Пароля нет намеренно — это честная
  договорённость, а не замок.
- **Облачная очередь.** Сданные рекорды не теряются при обрыве связи:
  копятся в браузере (до 200), уходят пачками по 20 с выдержкой, без
  повторного задваивания. Проверяет `tools/supabase-gate.py`.
