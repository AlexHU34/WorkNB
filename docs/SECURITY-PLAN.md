## 1. Важная оговорка — от чего зависит смысл защиты

«Накрутка» имеет смысл только если цифры видны кому-то ещё:

| Ситуация | Что возможно | Нужна ли защита |
|---|---|---|
| Рекорды только на устройстве игрока | накрутить можно, но вредит только ему | почти нет |
| Общий рейтинг игроков | полноценная накрутка | нужна, но только с сервером |
| Рекорды показываются друзьям | терпимая накрутка | достаточно сбить спешку |

**Вывод:** без сервера и без общего рейтинга полноценная защита невозможна
в принципе. Всё ниже — защита от небрежной правки, а не от целенаправленного
взлома.

## 2. Антинакрутка — что реально можно сделать

### Слой A. Сделать правку заметной (целостность)

Основа уже есть: `src/data/store.js` версионирован (`BB_SCHEMA = 3`,
ключ `bb2.v3.data`).

- Контрольная сумма по **всему** сохранённому блоку, а не по каждому полю
  отдельно. Иначе правится одно поле, а остальные «сходятся».
- **Цепочка хешей** для истории рекордов: `h[n] = H(h[n-1] + score + ts)`.
  Изменил любой старый результат — все последующие хеши перестают сходиться.
- При загрузке проверка целостности → честное предупреждение, а не тихое
  доверие к битым данным.

### Слой B. Сделать накрутку бессмысленной (правдоподобие)

Главная идея: **не доверять сохранённому числу**.

- Хранить не итоговый счёт, а **слепок лучшего забега** (последовательность
  действий / сид / ключевые моменты), а счёт пересчитывать из него.
- Проверка физической правдоподобности: время забега быстрее теоретического
  минимума движка → отклонять.
- Монотонность времени: рекорд не может быть раньше предыдущего и не может
  опережать реальное прошедшее время.
- Новый рекорд обязан строго превосходить старый, и разница должна
  объясняться слепком.

### Слой C. Сделать правку дорогой (обфускация)

- Минификация и манглинг имён через esbuild.
- Ключ выводится из нескольких разбросанных констант, а не лежит в коде
  открытым текстом.
- Единая контрольная сумма, чтобы нельзя было «починить» одно поле точечно.

### Слой D. Сделать накрутку невыгодной (главная защита)

Техника слабее мотивации. Если рекорд ни на что не влияет — накручивать
не будут. Поэтому: достижения привязать к **слепку**, а не к числу.

### Честный предел

Читая бандл, determined-читер пересчитает цепочку хешей. Защита поднимает
цену с «10 секунд в DevTools» до «надо повозиться» и надёжно останавливает
скучающих подростков и друзей. Массовую накрутку ради выгоды — нет.

## 3. DDoS — прямой ответ

**Если нет бэкенда — проблемы DDoS не существует.**

- Запрос игрока идёт на CDN, а не на твой компьютер. Твоего IP для атаки нет.
- Cloudflare Free, Pages и Netlify включают автоматическую L3/L4 защиту
  бесплатно и безлимитно.
- DDoS становится проблемой только когда запрос заставляет **твой** код
  считать. Бэкенда нет — жечь нечего.
- Остаточный риск: боты, выедающие квоту бесплатного тарифа. Acceptable.

**Итог:** работа = поставить статику за бесплатный CDN. Кода писать не нужно.

## 4. Чего НЕ делать

- Сервер, бэкенд, API, база данных
- Монетизация, реклама, платежи
- Облачные сохранения, аккаунты, синхронизация между устройствами
- Общий публичный рейтинг
- Аналитика и телеметрия
- Платные CDN / WAF / anti-DDoS / хостинг
- Сторонние anti-cheat SDK
