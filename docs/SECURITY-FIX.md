## Уже исправлено (в этом репозитории)

### 1. Кража через рейтинг (XSS) — закрыта

Было: имя из общего рейтинга вставлялось в страницу как разметка
(`innerHTML`), поэтому любой мог записать в базу HTML и выполнить свой
скрипт у всех игроков.

Сейчас (`src/app/app.js`, `renderHall`): имя, счёт и весь текст рейтинга
рисуются узлами с `textContent`; `innerHTML` в рейтинге нет вовсе.
Счёт дополнительно приводится к целому 0–999, имя обрезается до 20 знаков.

Проверка — `tools/security-gate.py`. Она не только читает код: открывает
собранную страницу в браузере, подсовывает рейтингу строку
`<img src=x onerror=...>` и требует, чтобы она осталась текстом, а код не
выполнился.

### 2. Подделка рекордов и «вечные» записи — правила на сервере

Новая миграция `supabase/migrations/v4_scores.sql`:

- политика вставки с проверкой: адрес игры `^[0-9A-Za-z_-]{1,40}$`,
  имя 1–20 знаков нашего алфавита без знаков на торцах, счёт 0–999;
- все прочие разрешающие политики вставки на `scores` снимаются
  (иначе они складываются по «или» и проверка бесполезна);
- время `created` ставит сервер, клиентское не принимается;
- ограничитель: не больше 10 записей на одну игру и имя в минуту;
- табличные ограничения как второй рубеж;
- в конце — уборка тестовых строк аудита (`sec-probe-%`, `tx-probe-%`).

`supabase/migrations/v4_noise.sql` — то же для `pings` и `client_errors`:
длины, запрет пустых, замена разрешающих политик вставки, ограничитель
10 отметок одного события в минуту, уборка тестовых строк.

### 3. Ники: подделка чужим именем — сужена

- ники сводятся к одной форме (`NFKC`), поэтому «полные» и обычные буквы
  больше не считаются разными никами;
- смесь кириллицы и латиницы запрещена — так подделывают чужое имя
  (`Аlex` с кириллической `А`);
- поиск свободного ника экранирует `_` и `%` (раньше `_` работал как
  шаблон и давал ложное «занято»).

### 4. Защита страниц и заголовки

- `404.html` получил такую же мету защиты, как остальные страницы;
- добавлен `_headers` — заголовки безопасности для Cloudflare Pages /
  Netlify: `frame-ancestors 'none'`, `X-Frame-Options: DENY`, HSTS,
  `Referrer-Policy`, `Permissions-Policy`, `nosniff`. GitHub Pages этот
  файл не читает (и не ломается от него), но при переезде на прокси
  защита включается сразу;
- добавлен `security.txt` — адрес для сообщений о дырах;
- адреса картинки для соцсетей и самой страницы переведены на свой домен.

## Что нужно сделать руками (из репозитория это не делается)

### A. HTTPS на домене — главное

Сейчас `https://aerisgames.ru` отдаёт сертификат `*.github.io`, то есть
HTTPS сломан, а сайт открывается по HTTP. Пока так, его можно подменить
по дороге, и офлайн-режим (воркер) на домене не включается.

1. GitHub → репозиторий `AlexHU34/WorkNB` → Settings → Pages →
   Custom domain: `aerisgames.ru` (сохранить).
2. GitHub покажет TXT-запись
   `_github-pages-challenge-alexhu34.aerisgames.ru` — добавить её у
   DNS-провайдера **до** повторного сохранения домена.
3. Дождаться выпуска сертификата (обычно от минут до 24 часов) и
   включить **Enforce HTTPS**.
4. Проверить: `http://aerisgames.ru` должен отвечать `301` на `https://`,
   а `https://` — открываться без предупреждения.
5. `www`: либо добавить вторым доменом, либо оставить CNAME; после
   верификации домена угон через CNAME закрыт.

### B. Применить миграции и убрать тестовые строки

Supabase → SQL Editor → выполнить по порядку целиком:

1. `supabase/migrations/v4_scores.sql`
2. `supabase/migrations/v4_noise.sql`

Проверить после:

```sql
select count(*) from public.scores
where game like 'sec-probe-%' or game like 'tx-probe-%';        -- 0

select count(*) from public.pings where event like 'tx-probe-%'; -- 0

select count(*) from public.client_errors where page='sec-probe';-- 0

select policyname, cmd, with_check
from pg_policies
where schemaname='public' and tablename='scores';               -- одна INSERT с проверкой
```

И повторить проверку из отчёта: `POST /rest/v1/scores` с HTML-ником и
счётом 2147483647 должен получить отказ (401/400/исключение), а не 201.

### C. Настройки Supabase

- Authentication → Providers → Email: выключить `Enable signups`
  (сайт auth не использует; иначе можно рассылать письма на чужие адреса).
- Authentication → Settings: `mailer_autoconfirm` оставить выключенным,
  раз signup выключен.
- Проверить, что `anon` не имеет прямого INSERT в `client_errors` и
  `pings` сверх новых политик — команды `pg_policies` выше.

### D. Настоящее ограничение частоты (когда появится прокси)

Серверные ограничители в миграциях отсекают залпы, но общий поток по
разным адресам идёт без счёта. Надёжный вариант — поставить сайт за
Cloudflare (или крайнюю функцию Supabase) и:

- включить WAF-правило: не больше N запросов в минуту на `/rest/v1/*`
  с одного адреса;
- при желании — Turnstile на сдачу рекорда;
- тогда `_headers` начнёт работать, и вместе с ним HSTS и запрет рамки.
